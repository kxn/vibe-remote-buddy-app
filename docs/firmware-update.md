# 接收器固件更新

设置页显示接收器当前版本和应用随附版本。仅当随附版本更新、设备支持更新 API、硬件目标相符时允许更新。录音期间不能更新。更新会暂时断开遥控器，完成后自动恢复连接。

正常更新通过原有 USB 管理接口，不需要网络、驱动安装或 BOOT 按钮。传输时可以取消；开始激活后等待设备重启。程序核对同一 USB 序列号、实际版本、应用槽和首次启动确认结果后才显示成功。无法确认不代表成功，需重新连接检查版本。

支持目标为 `s3-q2-ab1`（2 MB Quad PSRAM）和 `s3-o8-ab1`（8 MB Octal PSRAM），均支持 8/16 MB Quad Flash、双应用/双数据布局。0.8.0 的旧 target 需重新完整初始化，测试阶段不提供跨 target 迁移。C6、其他分区布局及早期开发固件不能直接更新。早期固件需另行完成一次完整安装。其他平台仍需实测。

## 发布时附带固件

App 公开仓库的 `receiver-firmware/` 保存三种目标的完整发布产物（q2、o8、q2-f4），包括更新清单和首次安装清单。`npm run firmware:import -- <发布目录>` 校验并导入产物；不导入源码、ELF、配对数据或完整 Flash 转储。

`npm run release` 校验固件，获取并锁定最新机型库提交，重新编译安装用机型数据库，嵌入更新固件并打包完整离线安装资源。可用 `BUDDY_FIRMWARE_DIR` 指定另一份完整发布产物。详情见 [发布流程](release-pipeline.md)。

清单字段：format=1、target、version、size、sha256、data_min、data_max、notes。版本采用 `主.次.修订` 三段非负整数。应用禁止同版本覆盖及降级。SHA256 用于完整性校验，不是作者签名；固件包随可信应用发行，不提供任意网络地址下载执行功能。

## 管理协议

沿用 Buddy v1 / RBP/3 会话与心跳。INFO 新增 `update_api=1`、`target`、`schema`、`bank`（0/1）、`confirmed`、`flash_bytes`、`psram_bytes`。

| 操作 | Opcode | 请求 / 返回 |
|---|---|---|
| 状态 | 0x420 | 返回 INFO 的更新字段及 state、offset、size、copied、error |
| 开始 | 0x421 | target/version/size/sha256/data_min/data_max；返回 chunk=192 |
| 数据 | 0x422 | offset、hex（1–192字节，小写十六进制）；返回下个 offset |
| 校验 | 0x423 | 完整数据后调用；长度、SHA256、ESP 镜像、项目与版本校验 |
| 激活 | 0x424 | 校验成功后切换启动槽，约750ms后重启 |
| 取消 | 0x425 | 激活前放弃；激活后返回 BUSY |

state：0空闲、1等待蓝牙退出、2复制配置、3接收、4校验完成、5即将重启、6失败。error 保留 ESP 原始错误码。状态轮询不推进状态，也不续传；15秒没有更新数据或管理会话消失会放弃未激活更新。准备期间客户端保持管理心跳。

重复数据仅在 offset、长度和已写字节完全吻合时成功；不能跳过字节。重连后重新开始完整更新。激活响应丢失必须重连核对，不重发取消。更新期间禁止配对、映射修改和录音。

固件只写未运行槽。新程序首次启动使用配置副本，健康确认前失败会回到原程序及原配置。未来格式迁移在副本内完成；未知格式拒绝启动，禁止擦除用户数据。回滚不保证保留新程序运行期间的修改。


0.12.0 起支持 ESP32-S3 SuperMini 的 4 MB Quad Flash + 2 MB Quad PSRAM（`s3-q2-f4-ab2`）。8/16 MB q2/o8 原目标保持原分区。各目标均保留双应用、双配置与双机型库；首次安装按实测容量选包，包含离线机型库。不能在普通 OTA 中交叉刷写不同分区目标。
