# 适配试录的恢复与诊断

- 录音超时、解码失败、读取录音失败只结束该次测试。取消后等待固件 idle，再 ARM；不因这些错误断开 BLE 或清除临时绑定。
- 固件 adapter_error 表示协议适配器失败，显示明确的重新连接入口。重新连接验证协议族及 Report Map，不要求重连广播重复名称。
- 只在按键验证阶段订阅报告 1、3、F8；音频通道由语音适配器订阅。
- 准备超时与录音超时分别计时；无音频期限从按键和协议就绪两者较晚者开始。
- 错误自动保存到应用本地数据目录 diagnostics/probe-latest.json，含命令耗时、状态、原始错误及布局草稿，不包含 PCM。最近最多 2048 条命令。
- 同一加密连接上的完整 HID Report Map 和 Report Reference 可复用。其他动态属性、写入和语音协商仍走实际 GATT；服务发现仍由适配器执行，未声称消除所有重复操作。

## 图片边界

内置外观保留结构图和透明点击区域。生成图片按按钮完整外接框验证圆角内边界及留白，整体缩放保持相对位置；不能仅检查矩形画布。联通最底排与圆角留出距离。布局变更不改变固件协议配置版本。

## 本轮验证

前端单元测试、适配向导宽/窄窗口和 HID/ICO 混合报告回归；固件准备期间按键、无音频重试、缓存连接隔离及完整固件回归。实际移动遥控器录音仍需真机复测，不能以模拟通知替代。

## 连接失败后的重新识别

- 选择列表只确定目标地址及地址类型，不作为可无限复用的连接凭证。识别前等待该目标最近一秒内的可连接广播，找到后立即连接；最多等待 30 秒。不同名称相同或更强信号的设备不能代替目标。
- 发现 SDK 错误、未结束的操作或清理错误时，先 END 并等待临时连接及临时绑定清理完成，再 BEGIN。正常已连接会话保留。清理失败必须报错，不越过失败继续连接。
- 识别和语音阶段的显式重连共用此路径；新候选的扫描代次及广播信息用于连接和型号指纹。
- 2026-09-19 日志确认旧界面重复使用 8.8 秒前的候选记录。CLI 新广播连接及加密成功，但这不能证明所有 GUI 首次失败均由候选过期导致；真实无线连接仍需复测。

录音失败后读取固件的可选分片元数据环（64 条，序号、片号、接收时间、片尾字段），随诊断保存。它不含完整压缩帧或 PCM，只用于区分通知缺失与帧尾校验不符；采集中不可读取，失败后冻结，新一轮 ARM 清空。界面保留 adapter_error 的具体原因，不再只显示“语音异常结束”。

## 0.8.4 实时试录

整段录音由电脑暂存，板端只有 16 KB 发送环。音频使用 `0x483` 管理事件，按 capture/offset 校验；不再使用逐块下载。缺块、接收超时、发送环满均明确失败，不把截断录音标记为通过。实际遥控器连续试录仍需硬件验证。

## 0.8.5 试录传输吞吐

0.8.4 在 COM15 上使用连续只读 INFO 请求实测约 53.7 KB/s，低于十六进制 PCM 事件所需约 75–90 KB/s。TinyUSB full-speed 默认 CDC TX transfer buffer 为 64 字节，USB 任务还有一拍让出；4096 字节软件 FIFO 不等于一次 USB 提交长度。

0.8.5 将 CDC TX transfer buffer 和每轮供给改为 512 字节（USB 描述符最大包仍为 64 字节），管理队列每轮最多发送 2048 字节并支持部分写入；PCM 不满 96 样本时等待合并，录音结束立即冲刷尾包。板端仍只有 8192 样本发送环。`VOICE_READ {transport:true}` 返回 capture/samples/sent/buffered/high_water/backpressure，自动诊断保存这些计数，不保存音频。错误改为“音频传输缓冲已满”，不再将板端吞吐不足归咎于电脑。

C 回归使用实际管理编码/队列、8 KB 串口 FIFO、每 4 ms 一次 USB 批量及持续 16 kHz PCM 数据；旧 64 字节批量复现积压超过 16 KB，新批量连续 60 秒通过，并校验 CRC、序号及部分写入恢复。此测试不替代遥控器实录。更新同一块板子到 0.8.5 后，同一 10 秒 INFO 测试测得 161,045 B/s（旧版 53,705 B/s），约 3 倍；真实语音仍需用户复测。

## 按键设置

视频会议预设使用 BM_VOICE（kind=3）的无修饰键空格（usage=44），保持按住/释放语义，不触发输入法切换。进入按键页或打开按键编辑前需遥控器 READY；离线弹窗等待方向键唤醒，可取消。读取前后检查身份及连接代次。每次有效修改短暂防抖后写接收器并回读，拒绝覆盖变化的 revision；失败不盲目自动重试。


## 0.8.6 准备计时

日志中 ARM 后 169 ms 即发生 65 秒准备超时。BLE pump 在处理 USB 命令前取 now，而 ARM 用稍后的 now_ms 设置 pv_prepare，无符号相减下溢。处理命令后重新取时，试录的准备、首包和停滞期限统一用有符号差值比较，支持短暂旧快照及 32 位时钟回绕。回归覆盖开始时间比 tick 晚 1 ms 与回绕边界。
