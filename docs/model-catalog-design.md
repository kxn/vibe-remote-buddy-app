# 社区机型库与接收器配置拆分方案

状态：设计建议，尚未修改资源格式、接收器匹配或同步协议。

## 当前问题

`src/core/models.ts` 的 RemoteModel 同时包含 family、matches、raw、keys.default 和 layout。extends 只在电脑上展开；展开后的每个型号仍占一个板端名额。syncModels 遍历整个本地库安装，未按实际使用下载。板端 BUDDY_MODELS=16，每项最多8条识别规则、64条原始映射，JSON上限6144字节。

广播阶段使用名称/前缀和厂商ID筛选；连接后主要以 HID Report Map CRC 校验。相同 CRC 对应多项会报歧义。名字不能唯一确定型号；CRC也不能证明键码、语音协议及真实按键集合完全相同。MAC只标识一台设备，不能进入社区同款匹配条件。

## 五层资源

| 层 | 内容 | 存放位置 |
| --- | --- | --- |
| 协议驱动 | ATVV、HID ICO、旧小米HID；协商、编解码、开关麦 | 固件代码 |
| 硬件配置 profile | 驱动参数、报告通道、原始键码→逻辑键；协议能力要求 | 电脑库；板子按需缓存 |
| 识别规则 fingerprint | 广播候选与连接后验证条件，引用profile；可给出variant提示 | 电脑完整库；板子保留在用及选装规则 |
| 外观型号 variant | 品牌名、按键标签、可见键集合、布局、图、默认功能；引用profile | 电脑；绑定记录只存ID/版本及所需默认映射 |
| 个人设备 binding | BLE身份/密钥、profile版本、variant ID、个人键位 | 板子持久化，电脑按身份关联 |

默认功能和原始键码不是同一张表：原始键码决定“这是返回键”，默认功能决定“返回键发Backspace”。用户重命名、拖动布局、改默认功能不应生成新的协议配置。

例如联通与移动若实测协议参数及键码完全一致，可共用 `hid-ico/common-v1`，分别引用 `unicom/...` 和 `cmcc/...` 外观型号。少数键码有差异时以基础profile加小型覆盖生成另一份运行配置；仅改标签不产生新profile。不能仅凭都叫ICO就合并，编解码器相同不意味着开麦命令、报告格式和按键一致。

## 同款识别

1. 扫描只产生候选：可连接、近距离；名称及厂商字段是线索，不是最终ID。
2. 连接后读取实际可用证据：PnP VID/PID、DIS型号、服务/特征集合、Report Map摘要、协议能力。使用必需条件的合取与备选规则的析取；缺失字段记为未知，不能当匹配。
3. 每条规则声明证据要求与profile。显式冲突先排除；多条规则若归于同一profile，可直接共用硬件路径，不能报“重复型号”。
4. profile不同且无法唯一确认，要求选择并验证，不能按配置文件顺序或名称猜。候选外观仅名字不同且运行兼容时允许选择外观，不重复配对。
5. 多个外观型号硬件完全一样时，无法靠蓝牙证明是哪一款。用广播名作外观建议；仍不确定时显示通用名、让用户选图，保存到该设备绑定中。
6. 使用稳定人工ID表示型号，使用规范化运行内容的SHA-256做去重。摘要不是“同款事实”，只有经证据验证的规则建立对应关系。保留原始Report Map摘要；规范化摘要只作附加证据，避免归一化抹掉重要差异。

已绑定重连优先使用绑定身份与固定profile版本，并核验硬件兼容性；社区更新不能在后台替换绑定协议或清除个人按键。

## 16个名额与脱离上位机使用

16目前是完整资源条目数，并非16种算法，也不是蓝牙同时连接数。近期不必盲目扩容：完整库只留电脑，板端缓存按需profile；已绑定引用和进行中操作引用必须锁定，淘汰仅限未引用缓存，写入采用事务。多variant共享一份profile。

未开上位机时，已绑定设备继续独立工作。未知遥控器自动配对仅覆盖板子已安装的规则；不能宣称电脑端整个社区库都能离线识别。用户可以提前安装常用兼容包。规则表也须计量内存/NVS成本，不能把无限名字塞进一个条目来绕开容量。是否提高缓存上限，应以2MB PSRAM目标的实测RAM/NVS预算决定。

绑定保存profile ID、内容摘要、variant ID及个人映射；外观缺失时按广播名/通用图降级，不能影响语音。按需安装、配对和适配继续调用统一连接/绑定事务，不另造流程。

## 社区Git与同步

建议独立公开仓库，仅放JSON/SVG/文档及许可证，不接收固件二进制或执行脚本。目录按 profiles / fingerprints / variants 分开，资源引用固定版本；避免任意多层继承，编译器展开并检测循环、缺失引用及冲突。

PR模板附去标识化的服务清单、设备信息、Report Map摘要、按键实测和语音结果。禁止上传MAC、绑定密钥、个人录音。CI验证schema、引用闭包、重复规则/歧义、边界、布局覆盖、运行编译结果；协议变化必须标记最低固件能力要求。相同硬件配置的重复贡献应新增variant或指纹规则，而非复制profile。

应用不需要内置git客户端。读取固定源发布的版本化目录索引，下载所需文件并校验摘要；索引与文件一起原子切换，可回滚。索引的哈希只防损坏，若需要防发布源篡改应增加签名与内置公钥。限制大小、路径、文件类型，SVG禁脚本/外链；只接受声明式数据。

社区库、用户本地覆盖、设备个人设置分层存放。本地覆盖不被同步覆盖；只更新社区库不会改已绑定设备，运行配置升级显示差异并由用户确认。初版提供手动“更新机型库”，不要先加后台强制更新。

## 实施顺序

1. 建立schema v2及离线编译器，以现有联通、移动、小米作兼容回归样本，证明同profile不同标签可共存。
2. 上位机加载社区库/本地覆盖；v1导入转换，不改变现有绑定语义。
3. 板端分离profile缓存与绑定variant，增加按需安装和引用锁定；沿用现有事务与失败恢复机制。
4. 分离profile识别与variant选择；覆盖同名不同协议、同CRC不同键码、同profile不同外观、字段缺失等歧义回归。
5. 最后接入Git发布索引和同步UI。新增驱动仍需更新固件，单纯变体通过资源即可支持。
