# 机型库格式2接入设计

旧版不可变 revision 文件结构已废弃，统一采用 [机型库 FORMAT.md](https://github.com/kxn/vibe-remote-buddy-models/blob/main/FORMAT.md) 的契约。公共库当前格式2、版本0.2.0；固定可读文件名，每个资源只有当前版，历史留在Git。

## 已完成与尚未接入

公共库完成四个样本的转换、RC003实机Map补采、默认资源拆分、独立个人override Schema、共享协议/布局、引用及摘要校验、识别与覆盖参考实现和回归测试。

本应用仍使用旧RemoteModel资源和MAP_GET/MAP_SET生效映射。`src/core/service.ts::saveMap` 没有独立保存override。不得把公共库Schema当成本应用已经支持个人覆盖或在线同步。不要直接将新库文件复制到旧resources/remotes。

## 唯一接入顺序

1. 实现固定commit的库加载与校验、默认快照存储；保持与公共库参考契约相同的识别结果，测试同名设备、资料缺失与歧义。公共库文件不可作为个人编辑目标。
2. 为每只绑定设备建立稳定身份，保存model ID和采用的默认快照；新增按按钮ID的稀疏override存储。恢复默认删除覆盖，none和等于默认的显式设置都保留。取消编辑不写入。
3. 旧映射迁移为显式override，不根据值相等推断继承。完整迁移成功前保留旧配置备份；未知型号保留旧生效配置，不自动套同名机型。
4. 引入统一“解析默认+覆盖→校验→编译→写入→回读→提交本地快照”的配置事务，各设置入口复用。配置代次变化时拒绝过期写入；断线重连核对设备实际版本，避免本地与板端各自显示成功。
5. 固件扩展共享硬件profile/每设备配置分离及来源元数据，支持跨电脑读取覆盖来源。扩展前对来源未知的配置全部保护为显式覆盖。按绑定引用安装/回收profile，不把整个库塞进16槽。
6. 最后接入Git同步入口；下载不等于采用新默认。用户采用更新时校验删除按钮、语义变化、驱动能力和覆盖冲突，失败保持旧快照。

## 实测约束

联通和移动的169B Map有4字节不同，普通键16个相同、11个不同；只共享ICO协议和三列28键几何，不能合并键表。RC003完整Map为86B、CRC32C 6bd7daad，已采8个Report Reference及ATVV通道；PnP和此次逐键重验未采。旧款小米2717:32BA走HID/mSBC；广播同名不能判成RC003。

上述接入包含应用、管理协议及板端存储变更，需要分别回归；当前仅更新设计文档，不宣称客户端已实现。
