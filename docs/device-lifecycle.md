# 遥控器管理流程

新增遥控器统一进入 `ProbeWorkbench`，使用同一个探测会话从扫描、连接、读取指纹，到选择机型、验证和移交正式绑定。发现列表共用 `candidateStream` 和 `NearbyCandidates`；默认按机型库扫描线索过滤，“显示所有机型”只放开机型过滤，仍保留可连接性和近距离门槛。已有绑定的“重新配对”继续使用修复操作，不能当作新增槽位。

搜索每15秒续期，30秒会话期限内不清空候选和选中项。候选游标跳过空槽，不并发堆积管理请求。停止搜索必须等待在途读取退出，之后才能连接。

需要接收器 `lifecycle_api=2`。管理扩展仍使用 RBP/3：

- `CANDIDATE {cursor}` 返回下一有效条目及递增 `next`；`next=24` 表示到尾部，没有 `candidate_id` 表示没有条目。紧凑读取不返回原始广播字节。
- `SCAN` 在现有会话内续期并保留 epoch；`SCAN_STOP` 后下一次搜索才重置候选。
- `PROBE_ADOPT {model_id}` 将当前诊断连接移交正式绑定，返回 `operation_id`。
- `RETRY {operation_id}` 重试失败的绑定操作。目标身份/型号属于操作记录，不从可能已复用的界面候选或设备槽重新猜测。

适配保存依次完成本地资源保存、同步资源、移交连接、等待绑定提交，然后显示完成。不再要求用户重复添加同一设备。已移交操作的桌面重试沿用操作编号；只有确实失败后才请求重连。绑定成功不要求遥控器查询时仍在线。

后续修改必须同时检查普通添加、适配保存、删除重加、休眠重连和失败重试；不得因某一入口失败再复制一份连接流程。新能力缺失时提示更新固件，不静默回退旧流程。


机型库迁移：旧本地 ID 与规范 ID 不能作为两个可识别型号并存。只有完整指纹条件（Map、PnP、服务、报告）及协议/原始键映射都一致时，才合并旧副本到唯一的规范型号；不以名称或 CRC 单独合并。个人显式编辑归入规范身份，已绑定槽位不随库修改。待配对机型列表和板端数据库必须使用同一份合并结果。旧文件已迁移时移出资源目录，发布包不得再次带回旧 ID。


## 统一添加和机型管理

- 连接后 `modelCandidates` 返回所有候选：精确 Map 在前，输入报告结构兼容的在后。必要的语音特征读写/通知能力不满足时不推荐模板。默认选中第一个候选；末项固定为未知适配。
- 精确 Map 只是排序证据。只有完整库指纹条件也满足，才能直接移交原机型。否则必须生成带本次实际证据的变体，并验证语音和键码。不能绕过板端已有的严格绑定校验。
- 机型资源 `onboarding.keyConfirmation` 控制精确机型是否确认按键（required/skip）；小米默认 skip，运营商机型 required。相近模板无论配置如何都要确认。
- 已知机型的按键确认是整页按下/松开状态，不弹逐键对话框。未知按键或丢报告不算通过。语音独立通知由 ICO 专用报告处理；ATVV 语音需要协议验证，不能等待不存在的 HID 释放码。
- 未知适配直接进入语音，再进入现有布局编辑；保留连接，保存后 `PROBE_ADOPT` 一次提交。目录去重生成的规范别名也用于移交，禁止向板端提交已合并掉的旧 ID。
- 高级里的机型库提供筛选、预览、修改名称/布局/默认功能/添加策略、恢复默认、连接验证、库更新和同步。不再提供第二个新遥控器适配入口。
- 本地默认修改放在应用配置目录 `model-overrides/<model-id>.json`，格式版本 1；公共库和已绑定槽位均不修改。修改使用临时文件原子替换，并保留一份 previous。取消编辑不落盘；连接接收器时保存后同步库，否则下次手动同步。
- 默认编辑不允许改变指纹、协议或键码身份。需要新增/删除物理按键时走同一添加向导选未知适配。
- 模板库更新采用当前指纹和原始映射，再覆盖用户可编辑字段；新增库按键保留原默认定义。板端 API 和槽位快照结构不变。
