# 遥控器管理流程

发现列表共用 `candidateStream` 和 `NearbyCandidates`。可连接性、信号门槛、滞回及排序只有一份实现；普通添加保留已知候选筛选，显式选择型号后允许识别附近未知候选，适配工具允许附近未知候选。

搜索每15秒续期，30秒会话期限内不清空候选和选中项。候选游标跳过空槽，不并发堆积管理请求。停止搜索必须等待在途读取退出，之后才能连接。

需要接收器 `lifecycle_api=2`。管理扩展仍使用 RBP/3：

- `CANDIDATE {cursor}` 返回下一有效条目及递增 `next`；`next=24` 表示到尾部，没有 `candidate_id` 表示没有条目。紧凑读取不返回原始广播字节。
- `SCAN` 在现有会话内续期并保留 epoch；`SCAN_STOP` 后下一次搜索才重置候选。
- `PROBE_ADOPT {model_id}` 将当前诊断连接移交正式绑定，返回 `operation_id`。
- `RETRY {operation_id}` 重试失败的绑定操作。目标身份/型号属于操作记录，不从可能已复用的界面候选或设备槽重新猜测。

适配保存依次完成本地资源保存、同步资源、移交连接、等待绑定提交，然后显示完成。不再要求用户重复添加同一设备。已移交操作的桌面重试沿用操作编号；只有确实失败后才请求重连。绑定成功不要求遥控器查询时仍在线。

后续修改必须同时检查普通添加、适配保存、删除重加、休眠重连和失败重试；不得因某一入口失败再复制一份连接流程。新能力缺失时提示更新固件，不静默回退旧流程。
