# 遥控器型号资源

从接收器固件 **0.6.0** 开始，相同协议的变种可以通过资源安装，不需要重新编译应用或刷写固件。首次启用此能力需要更新一次接收器。

Windows 便携目录：

```text
Vibe Remote Buddy.exe
resources/remotes/
  xiaomi.rc003/model.json
  xiaomi.rc003/artwork.svg
  unicom.sample-28/model.json
  unicom.sample-28/artwork.svg
  example.voice/model.json
```

应用启动读取资源，连接接收器后同步运行配置；修改文件后重新启动应用。macOS 打包资源位于应用的资源目录中，尚未完成 Mac 实机验证。资源不包含脚本，也不向板子传图片。

## 只改蓝牙名称的变种

新建 `resources/remotes/example.voice/model.json`：

```json
{
  "schema": 1,
  "id": "example.voice",
  "extends": "unicom.sample-28",
  "title": "我的语音遥控器",
  "revision": 1,
  "matches": [{ "name": "实际广播中的完整名称" }]
}
```

它继承联通协议、按钮、默认功能、布局和图片。应用与固件均不需要改代码。必须保留基础型号目录。此示例是编辑模板，并不表示已经验证了这个名称对应的真实设备。

继承按顶层字段覆盖：数组整体替换，不拼接；最多 8 层，拒绝循环和重复型号 ID。不要覆盖 `family`。不需要继承时，可以复制完整的型号 JSON 和图片，使用新的唯一 ID。

## 识别规则

`matches` 为 1–8 条规则，规则之间是“或”；单条规则的条件是“且”：

```json
"matches": [
  { "name": "完整名称", "company": 1234 },
  { "prefix": "另一种广播名称前缀" }
]
```

- `name` 精确匹配；`prefix` 前缀匹配；区分大小写，每条必须二选一。
- `company` 可选，十进制 0–65535，指 **BLE 广播 Manufacturer Specific Data 最前面两个字节的小端 Company Identifier**，不是 USB VID，也不是 Device Information/PnP ID。当前不提供 PnP ID 匹配；不知道广播厂商标识时省略它，不要猜。
- 名称和广播厂商仅用于发现候选；同名规则允许共存。连接后按完整 HID Report Map 的 CRC32C 匹配，并验证协议。多个型号拥有相同 Map 时，先用无歧义的名称/厂商规则区分；仍有歧义时，在添加窗口选择型号；显式选择也必须通过指纹和协议验证。配对后保存设备身份和型号 ID。`map_crc=0` 的 ATVV/联通资源只接受已验证的对应出厂 Map，不表示通配任意设备。
- 随机蓝牙地址不是型号标识。已配对设备沿用绑定身份和已选型号重连。
- 名称、厂商 ID 不参与音频解码。连接后仍检查协议所需的报告、特征、音频握手，匹配到名字不等于协议兼容。

## 协议类型

| family | 驱动 |
|---|---|
| 1 | 已验证的小米 RC003 HOGP/ATVV 流程及 IMA 音频 |
| 2 | 已验证的联通 HID/ICO 控制流程及 ICO 音频 |

这不是“所有小米”或“所有联通”通用承诺。不同分片、启动命令、握手、编码器仍需增加固件协议驱动。当前没有验证小米一代。

`map_crc: 0` 使用已测量的 HID 描述检查。确知变种仅改变描述、仍使用同一报告格式时，可以提供其完整 HID Report Map 的 CRC32C（十进制无符号 32 位）。驱动会核对该指纹，并继续检查必需的特征/报告和握手；该字段不是“忽略协议错误”。没有抓到实际描述时保留 0。

## 按钮与默认功能

`keys` 是此型号实际拥有的按钮列表：

```json
{ "id": 9, "label": "主页", "default": [1, 0, 74] }
```

ID 稳定，不是布局顺序。范围 1–63，不能重复；2 固定为语音键，现有协议族必须保留它。其余已有语义 ID 见现有资源，例如 1 电源、3–6 方向、7 确认、8 返回、9 主页、12/13 音量、23–34 数字及星井号。新物理按钮可使用未占用的 ID，并配置原始报告映射。不要为同一按钮随意改 ID。

`default` 是 `[kind, modifiers, value]`：

| kind | 含义 |
|---|---|
| 0 | 不执行，后两项为 0 |
| 1 | USB 键盘，修饰位掩码及 HID usage |
| 2 | Consumer 功能，修饰为 0，value 为 0–7 |
| 3 | 自定义语音快捷键，只能用于 ID 2 |
| 4 | 上位机动作编号，需应用运行且配置了对应动作 |
| 5 | 默认语音预设，只能用于 ID 2；value 1 豆包、2 微信 |
| 6 | 切换本遥控器的会议 / 普通语音模式，不能用于 ID 2；modifiers/value 均为 0 |

预设保留板端 Windows/Mac 默认快捷键选择。Consumer 的 0–7 依次为音量加、音量减、静音、播放暂停、下一首、上一首、停止、浏览器主页。

没有数字键的变种：复制基础 `keys`，删除数字按钮；同时在 `layout.buttons` 中删除相应按钮。不能只隐藏图片上的按钮却仍宣称它存在。

## 不同原始键码

固件 0.8.0 起，具有非零 `map_crc` 的适配型号使用完整采集表：普通报告 1、3 中未列出的 usage 一律忽略，不借用协议族的默认键码。联通 F8 语音控制仍由协议族处理。内置的 `map_crc: 0` 型号保留原有按键解释；非空规则替换其对应报告。

```json
"raw": [
  { "report": 1, "usage": 42, "key": 9 },
  { "report": 1, "usage": 82, "key": 3 }
]
```

当前可配置格式：报告 1 是 8 字节键盘数组（前两字节为零，后六字节为 usage），报告 3 是 2 字节小端 usage。规则最多 64 条，输出 key 必须在 `keys` 中，禁止覆盖音频报告。其他原始格式需要扩展驱动，不能通过改一个 ID 假装兼容。

## 外观与布局

`layout.width/height` 定义纵横比；`buttons` 中 `x/y` 是按钮中心的百分比，`width/height` 是相对外壳的百分比，`radius` 为圆角百分比。每个按钮必须恰好出现一次，不能超出外壳。

每个按钮可选 `fill/color/border`（六位十六进制颜色或 `transparent`），以及简短 `symbol` 文本。未设置符号时使用通用按钮图标。

`artwork` 是当前型号目录内的 SVG 文件名，不允许引用目录外路径。SVG 作为独立图片显示，不作为 HTML 注入。`thumbnailSymbols` 控制首页缩略图是否显示按钮符号；`angle` 控制缩略图倾斜角（−30 至 30 度）。首页和编辑页共用布局。

## 同步、持久化与更新

- 接收器最多存 16 个型号（含两个内置型号），**同时配对仍是 4 台**。每个型号的运行 JSON 小于 6144 字节。
- 接收器保存识别、按钮、原始映射、默认功能，断电保留；图片和布局留在应用目录。
- 配对仍由用户选择；关闭应用后的自动配对策略不变。新资源必须先连接应用完成一次安装，放文件本身不会让未连接的板子自动获得配置。
- 已配对型号的运行配置被固定，不自动覆盖用户设置。修改识别、键码或默认功能应提高 `revision`；首版拒绝覆盖仍被配对设备使用的运行配置，需要先解绑相关设备，或创建新的型号 ID。仅调整名称显示、布局和图片无需提高运行版本，也不触发板端写入。
- 删除电脑上的目录不会自动删除板子型号，避免换电脑时破坏已有配置。管理 API 提供删除未使用扩展型号；两个内置型号不能删除。
- 上传中断、校验失败不启用半份配置；重复连接时按运行内容 CRC 跳过未变配置。
- 无效资源在应用诊断/错误中显示，不阻止其他有效资源加载。容量不足、协议不支持、在用型号被修改等错误不会被当成安装成功。

开发测试：`npm test`。Windows 发布必须一起分发 exe 与 `resources`；Tauri 构建会复制资源目录，不能只取 exe。


已有遥控器的更多设置提供「型号默认配置」。可编辑键名、位置、尺寸和默认功能；保存用于新配对或恢复默认，现有设备的个人映射不被覆盖。协议、指纹、原始键码及按键集合不在此入口修改。修改后的资源保存在程序 resources/remotes，旧包留在隐藏备份目录；开发打包保留 user-edited 标记的本地修改，公开产物不包含这些本地修改。
布局可带 editorColumns（2–5）和 editorRows（8–16）。预设继承保留实际坐标和尺寸，按钮 cell 仅表示编辑网格位置，不改变预览坐标。


语音适配先初始化协议，再由板端学习触发并通过 USB 麦克风试录。
ATVV 控制触发的语音键不写入 HID raw 表；语音功能由协议开始/结束通知驱动。
HID 语音键仍保存实测 report/usage。布局阶段复用本轮试听证明。

### HID/mSBC 旧款小米（family=3）

接收器0.8.21起支持Report4命令、Report5状态、Report6/7/8语音的协议族。
工作台依据报告拓扑提出候选，仍须通过语音试听；仅发现服务不代表兼容。
已验证型号使用16kHz mSBC。键位通过适配工具学习后保存，不从ATVV型号推断。
