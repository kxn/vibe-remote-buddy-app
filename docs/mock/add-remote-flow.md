# 统一添加遥控器入口（交互提案）

入口：`add-remote.html`。这是独立 mock，不调用接收器、不申请麦克风、不写配置。
紫色区域全部是模拟操作，不进入成品。布局快照来自当前机型库；移动示例特意设置两个候选，用于检查下拉切换，不代表实际指纹结果。

## 主路径

1. 打开即持续搜索近距离、可连接设备。默认只显示机型库中有扫描线索的设备；“显示所有机型”仅放开机型过滤，不放开距离和可连接性过滤。先强后弱进入列表，后续保持顺序和选择。
2. 选择设备并连接。连接后读取指纹，查找所有符合的机型。扫描阶段的名称等线索不作为最终身份结论。
3. 左侧下拉选择候选，右侧同步展示真实布局。单一候选默认选中；末项始终是“未知遥控器需要适配”。没有候选直接选该项。
4. 已知机型根据添加策略分支：小米直接添加；需要确认的机型显示整页布局，逐键按下和松开后变绿，全部确认才允许添加。不得为每个按键弹窗。
5. 未知机型沿用当前连接，直接确认语音，再编辑布局和采集键码。语音证明复用，不在布局阶段重复录音。可以复制现有布局，但须确认替换；普通按键重新验证。
6. 保存配置后自动完成添加，成功回首页。不得要求用户再搜索、再配对一次。

## 实现时的数据和连接约束

- 建议在版本化机型定义加入 `onboarding.keyConfirmation: "required" | "skip"`，由机型策略决定，不在 UI 按品牌名硬编码。mock 中的 `confirmKeys` 只是演示字段。
- 验证要对比实际报告和预期键码；不匹配不能直接染绿，应允许修正适配。不能只统计收到了几次按键。
- 全程由一个会话拥有连接。返回机型选择不重新建立连接；返回扫描或退出才释放临时连接。语音准备复用已有协议状态。
- 配置写入与设备正式接入成功后，原子提交槽位。连接、验证和布局编辑都不提前占用正式槽位。失败可在同一会话重试，取消清理临时状态。
- 语音协议无法支持时明确告知，不把发现服务等同于音频验证成功。
- 机型识别仍以库的有效指纹为准。此流程不引入按名称强行选择机型的 fallback。

## 布局与反馈

固定对话框头部、底部操作区、状态行高度；中间内容独立滚动。进度与错误不推挤按钮。重试不清掉已选择的设备和已经完成的步骤。

## 预览路线

- 小米：选择 → 连接 → 布局预览 → 下一步 → 完成。
- 移动：连接 → 切换候选查看布局 → 下一步 → 逐键确认（紫色区可以模拟全部）→ 添加。
- 未知：勾选显示所有机型 → Bluetooth remote → 连接 → 下一步 → 长按紫色模拟语音按钮后松开 → 试听、确认声音 → 布局 → 保存并添加。
- 紫色“连接结果”可切到连接失败或没有设备；重新开始清理未完成模拟任务。
