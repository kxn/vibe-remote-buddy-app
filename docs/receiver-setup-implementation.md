# 初始化接收器实施计划

基于已确认的三步向导，保留现有添加遥控器弹窗。

1. 内部构建生成完整安装包（四段镜像、地址、SHA256、目标规格）；应用构建可选附带，公开仓库不保存固件。
2. 使用锁定版本 esptool 的独立烧录助手，随 Windows 便携包分发。桌面端不需要 Python/ESP-IDF。辅助进程只处理程序指定的包、串口和操作，输出结构化状态及原始错误。
3. 后台仅枚举潜在 USB 接口。用户选择后才连接检查；检查结果以原生端票据绑定芯片 MAC、端口、版本及有效期。擦除前在同一串口连接中重新读取 MAC、安全状态、Flash，全部相符才继续；禁止 force。
4. PSRAM 不能自动确认时，按用户批准允许核对板型后显式确认 8 MB Octal PSRAM；已检测出不兼容容量时禁止继续。不能把人工确认表述成自动检查通过。
5. 独立原生状态锁负责串口互斥、重复调用和关闭保护。写入使用完整安装包，先全部校验，明确确认后才擦除。写后 esptool 校验并重启，再由现有管理协议核对同 MAC 接收器、版本、目标和启动确认。
6. React 向导复用应用样式和 Dialog，统一两入口；BOOT 操作后被动枚举，身份不明确时重新选择，不能按第一个端口自动刷。
7. 测试安装包损坏、地址错误、设备不匹配、确认过期、未知 PSRAM、错误及非交互 UI 流程。构建完整包。真机擦除仅由用户向导确认触发，本次开发验证不擅自擦板。

Windows 首版；其他平台显示暂不支持初始化，不妨碍应用原有功能。系统强制终止/断电无法完全禁止，需要 BOOT 恢复。

## 0.8.1 两类内存构建

安装目录改为 catalog.json + q2/ + o8/，两者版本必须一致，缺包或损坏在探测前拒绝。2 MB 内置 PSRAM 自动选 q2，8 MB 自动选 o8；未知外置内存显示规格选择和核对确认。仅支持 8/16 MB Quad Flash。安装完成核对选中 target；OTA 由接收器 target 选择内嵌包，交叉镜像被描述符检查拒绝。旧单一 target 无自动转换路径。

2026-09-19：正式向导在 16 MB Flash + 2 MB Quad PSRAM 板通过自动进入 ROM、自动选 q2、全片安装校验、重枚举和就绪检查。后端 USB OTA 实测从 bank 0 更新到 bank 1 并健康确认。模拟 UI 在 1000/440 CSS px 下通过，安装助手 11 项、应用 70 项回归通过。语音负载仍需后续遥控器实测。


## 0.12.0：4 MB 主力目标

安装包增加q2-f4（s3-q2-f4-ab2），匹配4 MB Quad Flash + 2 MB Quad PSRAM。q2/o8原目标保持8/16 MB支持。format2安装清单包含工厂NVS和离线机型库，擦除前验证目标的精确分区表，禁止仅更改Flash容量校验后刷8 MB包。安装成功后的硬件核验同样按目标校验4/8/16 MB，不能把4 MB已成功启动的板子误判为失败。

新板库容量576 KiB；机型库二进制格式2共享按键记录和键表、用二进制字段保存完整指纹，应用根据接收器报告的格式和容量编译并预检。GitHub资源格式2、个人override和已配对快照不变。旧接收器仍发送板端格式1。


SuperMini实机确认：工厂NVS写入应用data0银行（通过nvs_open重定向使用），不是系统nvs；首次启动立即获得6款离线库。USB Serial/JTAG使用esptool watchdog reset退出下载模式，避免RTS重置仍停在ROM。其余传输保留既有reset。每次完整安装仍先核对MAC及安全状态，再写后验证，不自动重试擦写。


## 2026-09-22：旧缓存覆盖新库回归

SuperMini首次安装附带0.2.3库，但catalog_resources无条件优先active缓存，使本机0.2.0（7d0d422…）隐藏新库。同步后重新添加的RC003和旧小米独立快照都缺Report 1 / Usage 62 → voice，普通键仍工作。修复为验证完整快照后按语义版本选择较新者，同版优先随包；旧缓存无效时使用已验证随包库，下载新版仍可优先。更新激活禁止降级，更新后的资源加载走同一选择入口，不直接绕过选择策略载入stage结果。

历史user-edited整机文件只覆盖可编辑外观、名称、默认动作，不替换官方协议、指纹及raw键表；现代model-overrides规则不变。已有绑定不随库升级自动重写，本次利用既有精确缺陷迁移修复两份已知旧表，保留配对和个人设置。实机分别观察RC003、旧小米按下、启动和松手正常结束，用户确认恢复。
