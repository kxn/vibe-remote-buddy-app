# 首次安装 / 恢复接收器：流程设计（尚未实现刷写）

交互预览：`docs/mock/receiver-setup.html`。所有设备、规格和进度是模拟数据，不可据此宣称已具备 PSRAM 探测或自动刷机能力。

界面文案遵循 [UI 设计规范](ui-guidelines.md)。流程意图保留在本文档；预览中的场景控件与模拟说明使用紫色并标记「仅预览」，不属于成品。正常界面只保留状态、必要操作和破坏性后果。

## 入口与发现

- 未连接接收器且枚举到潜在 ESP 下载接口时，右上角显示「初始化接收器」。只是提示候选；串口名称、VID/PID 不能证明芯片是 S3 或能自动进入下载模式。USB-UART 芯片也可能连接其他 MCU。
- 设置 → 高级始终提供同名入口，进入同一对话框；无候选时等待插入并提供 BOOT 操作。自动枚举不能扫描所有串口发送复位或握手。
- 用户选中设备后「检查设备」才允许尝试复位；事先说明会暂时中断原程序，但不擦数据。多个设备不默认选择，更不能选完后因列表变化切换目标。

## 向导

1. **选择设备**：端口、USB 名称和序列号后缀。建议通过拔插区分。没有设备时给出数据线/BOOT 检查。
2. **检查设备**：尝试进入 ROM 下载模式、确认芯片身份、安全状态、Flash 与目标板级规格、安装包完整性。自动进入失败才展开 BOOT + RESET 或 BOOT + 拔插说明；重枚举后重新匹配身份，多候选无法唯一关联时要求重新选择。
3. **确认安装**：展示芯片、设备标识、硬件规格、固件版本；明确全片擦除会丢失原固件及所有持久数据，无自动备份。未勾选确认前禁用「清除并安装」。切换设备或断连后确认失效；擦除前再次核对 ROM 芯片身份与清单。检测失败、保护开启、规格未知或无安装包均不能继续，不能提供强制覆盖绕过。
4. **安装与确认**：清除 → 写入完整镜像集 → 校验 → 重启 → 确认同一接收器版本及运行状态。擦写中禁用返回、关闭和重复操作；正式应用还需阻止托盘退出并处理系统关机请求。异常断电不能阻止，应保存可恢复诊断。写入成功不等于安装完成。

取消选择/检查后的流程不擦除；检查可能已把设备留在 ROM 下载模式，正式实现应尝试复位回原程序并在无法复位时提示用户按 RESET。擦写开始后不提供取消。

## 边界

- 当前包只支持既定 S3 / 16 MB Flash / 8 MB Octal PSRAM 目标。ROM/esptool 不能被假定能可靠识别所有外置 PSRAM；实现阶段需要经验证的只在 RAM 运行的检测程序或确定的板型信息。无法证实时停在「无法确认硬件规格」，绝不伪造检查通过。
- 完整安装包必须包含 bootloader、分区表、初始 OTA 数据、应用及校验清单，不能拿当前 OTA receiver.bin 单独完成初始化。正常固件升级继续用现有双分区接口，不应走擦除流程。
- 公开应用不自动获得私有固件；未附带有效安装包时显示「没有可用的安装包」，不允许进入擦写。
- 写入失败：显示阶段、原始错误和恢复方法，重新检查同一设备并再次确认后才能重试。校验成功但重启超时：只提供重新检测，不自动擦除重刷。
- UI 普通用户只需读操作说明；芯片细节和原始错误放折叠详情。此阶段只评审交互，不接串口、不刷板子。

## 预览场景

正常自动安装、手动 BOOT、多个候选、无设备、非 S3、未知硬件规格、安全保护、无安装包、确认后拔出、写入中断、写入成功未重连。两个入口、破坏性确认与错误恢复均可点击验证。
