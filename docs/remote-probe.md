# 遥控器适配工具

入口：设置 → 高级 → 遥控器适配工具。完整流程要求固件 0.8.12 或更新版本，能力字段 `probe_api: 1` 和 `probe_voice_api: 5`。应用附带匹配固件，可先在接收器更新页面升级。

## 使用流程

1. **发现设备**：让遥控器进入配对模式并靠近接收器。连续扫描，仅显示可连接设备，只接纳 −55 dBm 及以上设备，已显示设备使用 5 dB 滞回，5 秒未见移除。按首次入列的信号强度排列，后续 RSSI 波动不改变已有设备的相对顺序。已添加设备不可在这里重新配对。
2. **连接与识别**：选自动识别、小米 ATVV 或联通 HID/ICO，连接、加密并读取设备名称、制造商、PnP ID、HID Report Map、Report Reference 等属性。协议下拉框默认自动识别；识别成功先验证语音，试听通过后进入布局，失败才显示诊断和重试。特征不匹配不能继续。这一步不是语音兼容性证明。
3. **按键与布局**：左侧按布局列数显示网格，右侧标准按键库；拖动放置和换位，单击空格可选标准类型或自定义名称。标准功能 ID 固定，自定义使用 35–63；同名标准键不能另建为自定义。键盘用户可以在空格按 Enter 打开选择框。小窗口上下排列，按键库独立滚动。
4. **逐键验证**：单击布局按钮，按下并松开物理键。按下、松开分别实时点亮；完整采集后停留 0.5 秒自动确认，语音键复用本轮前置试听结果。记录实际 report/usage，不继承未经采集的模板键码。重复映射、同时按多个键或报告漏读会提示。取消重测保留之前确认的结果，移除按钮会删除对应验证结果。
5. **前置语音验证**：识别后先完成通知订阅与语音协商，准备完成后按住语音键说约3秒并松开。板端在收到通知时学习语音触发，立即交给正常语音处理流程，并使用正常 USB 麦克风通路，上位机打开明确匹配的接收器麦克风录制，不通过管理串口传音频。首次需要麦克风权限；匹配不到设备或匹配多只设备时停止。等板端尾音排空后结束录制，试听并确认声音正常。试录等待/录制总上限90秒。布局中的普通键继续逐个验证，不重新准备语音。
6. **保存型号**：全部放置按键和语音均验证后，在布局页直接点击“保存并使用”。“保存并使用”将资源放到程序旁 `resources/remotes/<id>`，结束临时连接、清理临时绑定，再同步板端型号表。若本机保存成功但同步失败，可直接重试同步。保存后可点击“添加这只遥控器”继续配对。

## 保存的内容

布局自动生成 `artwork.svg`，与型号一并保存在程序资源目录，首页直接使用矢量图片。

`model.json` 包含型号指纹、功能 ID、默认动作、布局及精确采集表。`probe-evidence.json` 保留设备信息、有限原始报告、错误和验证结果；录音不写入该文件。

联通语音验证会额外保留并导出原始 ICO 帧及 PCM 参考。成功采集后可分别下载 `.ico`（每帧原始 40 字节，保留遥控器原始混淆）、`.pcm`（每帧 320 个 signed 16-bit little-endian 样本）、`.wav`（同一 PCM）和 `.json`（逐帧 BLE 组序号）。固件只在帧序号连续、无 PLC 填充、原始帧与 PCM 一一对应且传输完整时提供数据；缺帧、末尾分组不完整或超过 10 秒会拒绝原始导出。ICO 文件不带 BLE 分片头、校验尾或后续字节，也不会预先做 permutation/XOR。

适配工具生成的 `map_crc` 非零，绑定完整且唯一的 HID Report Map。固件 0.8.0 对此类型号的普通报告 1/3 使用完整采集表，未定义 usage 忽略，防止遗漏键位又借用旧模板。联通 F8 语音属于协议族控制流程。

名称及广播厂商 ID 可构成识别规则；随机蓝牙地址不能作为型号身份。PnP VID/PID 当前作为诊断证据，不会写成固件不支持的指纹字段。

## 错误与能力边界

SDK 7（0x07）为 NimBLE `BLE_HS_ENOTCONN`，表示操作时连接已经不存在，不等同于协议不兼容。诊断保留失败步骤、句柄、原始 SDK/ATT/HCI 错误和断开原因。语音还保留解码错误、流结束原因及协议适配器错误。

当前可配置普通按键格式为报告 1 的 8 字节键盘数据、报告 3 的 2 字节 usage，以及联通 F8 语音控制。不同服务、数据格式或音频算法仍需修改协议族驱动，不能仅靠改名适配。

探测占用一条临时 BLE 连接，保护已有绑定。探测期间暂停自动配对/重连及普通遥控器的新语音请求。测试连接不向 USB HID 或 USB 麦克风输出，不调用输入法。退出、管理会话丢失、USB 重置或断链会清理测试适配器与音频缓冲；只删除本次新增的临时绑定。

语音捕获使用 320 KB PSRAM（16 kHz、单声道、16 bit、10 秒），按需分配，退出释放。管理接口在录音完成后分块读回，不依赖实时 USB 消费速度，不改变正常音频输出通路。

## 构建与验证

必须使用 `npm run release` 打生产包（Tauri custom-protocol），不可用普通 Cargo release 代替。发布包包括程序与完整资源目录。

自动测试覆盖协议数据与解码、边界、真实 React 界面交互（模拟硬件接口）、150% DPI。新适配工作台的真实遥控器录音及临时配对清理仍需上板验收，不把模拟接口测试视为硬件实测。


## 布局预设与异常恢复

“从已有布局复制”仅复制按键功能、名称和位置，目标型号的协议、指纹、HID Map CRC 保持不变；当前布局非空时需确认替换，加载后清空所有键码验证结果。密集预设使用最多 16 行的编辑网格，按键名称在验证窗口中修改。全部按键重新验证、语音试听确认后才可保存。

语音取消后若适配器仍无法空闲或已经报错，重试会结束临时探测会话并重新发现同一地址的遥控器，重新校验协议与 HID Map，再准备录音。不通过修改“按键已松开”标记掩盖故障。重新发现失败会明确提示进入配对模式；已有布局及验证结果保留。

首页按型号布局绘制单层图片，图片高度不超过 170px，按键限制在外壳内部；装饰圈处于独立底层，不覆盖遥控器。

识别协议后立即初始化语音通道。按住语音说话并松开，板端学习 HID 键码或 ATVV 控制触发，上位机通过 USB 麦克风录音。试听确认后编辑布局，语音键复用本轮验证，不再重复按键学习。
